# การกู้คืน BLE ใน UWB Board Programmer 2.8.3

เปิด `START_HERE_2_8_3.cmd` หรือ Shortcut รุ่น 2.8.3 รุ่นเดิมยังเก็บไว้ครบ

## สิ่งที่พบจากอาการ A3

บันทึกวันที่ 6 พฤศจิกายน 2026 ระบุว่า A3 ส่งเฟรมสุดท้ายเวลา 11:46:46 น.
และได้รับเหตุการณ์ตัดการเชื่อมต่อเวลา 11:46:58 น. ตามเวลาไทย ก่อนหน้านั้น
มี `firmware_queue_loss` หลายครั้ง ข้อมูลนี้ยังไม่พิสูจน์ว่าไฟเลี้ยง สัญญาณ RF
หรือเฟิร์มแวร์เป็นต้นเหตุของการหยุดส่งครั้งแรก

พบปัญหาการกู้คืนในโปรแกรมรุ่นก่อน: โปรแกรมจะเชื่อมกลับก็ต่อเมื่อได้รับ
advertisement ใหม่ภายในสามวินาที แต่บอร์ดที่ Windows ยังเชื่อมอยู่อาจไม่ประกาศ
ตัว จึงเกิดสภาวะรอค้าง แม้บอร์ดยังทำงานได้ การปิดโปรแกรมเดิมเคยทำให้ Windows
ปล่อย A1/A3 และสแกนพบอีกครั้ง

อีกครั้งหนึ่ง A3 ยังไม่ประกาศหลัง Windows ปล่อยทุก connection แล้ว ต้องเปลี่ยน
ไฟเลี้ยงและบูตบอร์ดใหม่จึงกลับมา การทดสอบบน USB แยกจาก PowerBank จึงจำเป็น
และยังไม่ควรสรุปว่า PowerBank เป็นสาเหตุแน่นอนโดยไม่มีข้อมูลเพิ่ม

## สิ่งที่แก้

- เชื่อมกลับจาก BLEDevice ที่เคยพบ โดยตรวจ UWB MAC, role และ CRC ทุกครั้ง
- ตั้ง watchdog ของข้อมูลสด เพื่อปล่อยและเชื่อมใหม่เมื่อข้อมูลเงียบค้าง
- แต่ละบอร์ดมี retry ของตัวเอง เว้นระยะสูงสุด 15 วินาที บอร์ดอื่นยังรับข้อมูลได้
- ทำ handshake ทีละบอร์ดเพื่อลดการแย่ง Bluetooth adapter ตอนเชื่อมต่อ
- ปิด notifications และยกเลิก MaintainConnection ของ session ที่โปรแกรมเป็นเจ้าของ
- ถอน native event handlers และรอ cleanup ให้เสร็จ แม้งานรับข้อมูลถูกยกเลิก
- บันทึกเหตุผลของการหลุดและ retry พร้อมแสดงสถานะ reconnecting

การเปลี่ยน connection จะเริ่ม clock/receiver epoch ใหม่ ไม่ส่งพิกัดเก่าซ้ำ
เป็นพิกัดสด ไม่ผ่อนการตรวจตัวตน และไม่รีเซ็ตวิทยุ UWB ของบอร์ด

Microsoft อธิบายว่า MaintainConnection=true ทำให้ Windows รอและเชื่อมอุปกรณ์
กลับเอง และต้องปล่อย device references ให้ครบจึงตัดการเชื่อมต่อจริง ดู
[MaintainConnection](https://learn.microsoft.com/en-us/uwp/api/windows.devices.bluetooth.genericattributeprofile.gattsession.maintainconnection)
และ [GATT client](https://learn.microsoft.com/en-us/windows/apps/develop/devices-sensors/gatt-client)

## ใช้งานเมื่อบอร์ดหาย

ปล่อยให้โปรแกรม retry อัตโนมัติก่อน ตรวจ Activity log ของ Anchor นั้น ถ้าบอร์ด
ไม่มีไฟ หรือ BLE/เฟิร์มแวร์ไม่ตอบ โปรแกรมจะรายงานและ retry ต่อ แต่ไม่สามารถ
เปิดไฟเลี้ยงให้บอร์ดจากระยะไกลได้ ใช้ไฟเลี้ยงที่จ่ายต่อเนื่องและตรวจสาย/ขั้วต่อ
หากไฟเลี้ยงมีการตัดหรือบอร์ดรีบูต

ไม่ต้อง Flash Firmware เพื่อใช้การแก้ฝั่ง PC นี้ โปรไฟล์ พิกัดที่สอบเทียบไว้
และข้อมูล RTLS เดิมยังใช้ต่อได้ การแก้ Alignment เป็นงานแยกจาก BLE
