# UWB Board Programmer 2.8.0 — จัดพิกัด Survey ให้ตรงกับ RTLS

เปิด START_HERE_2_8_0.cmd หรือ Shortcut รุ่น 2.8.0 โปรแกรมเก่ายังอยู่ครบ ไม่ต้อง Flash Firmware ใหม่เพื่อเปลี่ยนจุดกำเนิดของแผนที่ Tag ยังใช้ถ่าน CR2032 และ BLE ได้ตามเดิม

## ขั้นตอนใช้งาน

1. หน้า RTLS Platform ใช้ Use gateway configuration เพื่อเลือก Site/Floor ที่ถูกต้องและจับคู่ UWB MAC กับ Anchor ID บนเซิร์ฟเวอร์ ที่อยู่ BLE เป็นคนละค่า หาก API ไม่ส่งขนาดพื้นที่ ให้กรอกเองในขั้น Align
2. ทำ Auto Survey โดยเก็บระยะจากจุดอ้างอิง Tag ที่วัดจริงสี่จุด ตำแหน่งที่ได้ยังอ้างอิงเสาอากาศ Tag ณ จุด Survey Origin เมื่อบันทึกแล้ว โปรแกรมจะเปิดขั้น Align survey to floor ให้ต่อ ผลสำรวจถูกบันทึกก่อนแล้ว การยกเลิก Align จึงไม่ทำให้ข้อมูลสูญหาย
3. หรือกด Align survey to floor ในหน้า Survey & calibration ภายหลัง เลือก Anchor อ้างอิง ระบุพิกัด Floor ที่ต้องการและมุมหมุนแกน เลือกอ้างอิง Survey Origin เองก็ได้ หรือใช้คู่จุด Survey/Floor อย่างน้อยสองจุดที่มีระยะห่างแนวราบเพื่อหามุมและระยะเลื่อน แกน Z ต้องตั้งตรงอยู่แล้ว แนะนำสามจุดขึ้นไปและจุดตรวจอิสระ
4. ตรวจ Origin, ขนาด X/Y/Z, Elevation และ Level index โดย Level index เป็นลำดับชั้น ส่วน Z ที่ส่ง RTLS เป็นความสูงจากพื้นชั้น โปรแกรมไม่บวก Elevation ของอาคารซ้ำ
5. กด Preview alignment ตรวจพิกัด Anchors ทุกตัว จุดนอกขอบเขตจะมีคำเตือนโดยไม่ตัดพิกัดเข้ากรอบ สามารถกรอกจุดตรวจอิสระเพื่อดูความคลาดเคลื่อนของการจับคู่กรอบได้ จากนั้นยืนยันแกนและระดับอ้างอิง Z แล้วกดใช้โปรไฟล์ โปรแกรมบันทึก floor-profile ใหม่และเก็บ Survey ต้นฉบับใน metadata
6. กด Check configuration และ Connect RTLS จากนั้นเชื่อม BLE และเริ่ม positioning โปรแกรมส่งเฉพาะพิกัดสดที่ผ่านเกณฑ์ ค่าประมาณและจุดค้างยังแสดงเฉพาะในเครื่อง

## ตัวอย่าง A4 เป็น (0,0)

เลือก A4 เป็น Anchor อ้างอิง กำหนด Floor X/Y เป็น 0 และเลือกคง Z เดิมเมื่อ Z เดิมเป็นความสูงจากพื้นอยู่แล้ว กรณีนี้ไม่ได้ทำให้ A4 อยู่ที่พื้น Z=0

จาก A4 เดิม (-1.132,-0.426,0.518) ไปเป็น (0,0,0.518) ต้องใช้มุมหมุน 0 องศา และระยะเลื่อน (+1.132,+0.426,0) เมตร โดย Floor มีขอบเขต (0,0,0) ถึง (4,4,2)

| Anchor | Floor X | Floor Y | Floor Z |
| --- | --- | --- | --- |
| A1 | 0.688 | 0.878 | 0.891 |
| A2 | 2.013 | 0.895 | 1.891 |
| A3 | 2.450 | 0.037 | 0.779 |
| A4 | 0 | 0 | 0.518 |

ตัวอย่างนี้ตรงกับข้อมูลตั้งค่าที่ให้มา การตรงกันเชิงพิกัดไม่ได้ยืนยันความแม่นยำ RF หรือพิสูจน์ระดับพื้นจากการวัดอิสระ

## การป้องกันกรอบปะปน

โปรไฟล์เก่าจะแสดง Unmapped จนกว่าจะตรวจกรอบพิกัด การยืนยันว่าเคยวัด Anchors แล้วไม่ได้ยืนยันโดยอัตโนมัติว่าเป็น Floor frame ใช้ข้อมูล Survey ทดสอบในเครื่องต่อได้ แต่การตรวจ/ส่งพิกัด RTLS ต้องเป็น Floor ที่ยืนยันแล้ว

Align ซ้ำจะเริ่มจาก Survey ที่เก็บไว้ ไม่บวก offset ซ้ำลงค่าที่แปลงแล้ว หากแก้ตำแหน่งหรือ Site/Floor ของโปรไฟล์ที่ Align แล้ว โปรแกรมจะให้ตรวจใหม่ ใช้ Use retained survey เพื่อคืนพิกัดต้นฉบับเป็นไฟล์ใหม่ จากนั้น Align ใหม่ได้ พิกัดที่นำเข้าจากเซิร์ฟเวอร์สามารถยืนยันว่าเป็น Floor ได้อย่างชัดเจนเช่นกัน

โปรแกรมใช้ Anchors และทิศทาง AoA ที่แปลงเป็น Floor แล้วในการคำนวณโดยตรง ดังนั้น Tag, ความไม่แน่นอน, แผนที่, Path และข้อมูลส่งออกอยู่ใน Floor พร้อมกัน ไม่มีการบวก offset ที่ Tag อีกรอบ ผลสำรวจเดิมและ transform ยังเก็บไว้ตรวจสอบได้ การบันทึก/replay มีกรอบกำกับและ replay ไม่ส่งไป cloud

การจัดกรอบนี้ไม่แทนการสอบเทียบ antenna delay, clock หรือความคลาดเคลื่อนจากสัญญาณสะท้อน UI ภาษาไทย/อังกฤษ แผง Dock และ Path 30 วินาทียังคงใช้งานได้ ข้อมูล Token เข้ารหัสด้วย Windows DPAPI เฉพาะผู้ใช้และไม่รวมอยู่ในชุดแจกหรือ GitHub
