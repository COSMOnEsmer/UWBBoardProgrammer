# UWB Board Programmer — คู่มือผู้ใช้

เวอร์ชัน 2.0.1 โปรแกรมนี้แยกจาก RTLSSimulator และเก็บโฟลเดอร์โปรแกรมเดิมไว้ ยังไม่มีบอร์ด UWB เชื่อมต่อระหว่างพัฒนาซอฟต์แวร์

## 1. เปิดโปรแกรมและเลือกโหมด

ดับเบิลคลิก Shortcut **UWB Board Programmer** บน Desktop หรือไฟล์ `Start_UWB_Board_Programmer_v3.cmd` เลือก English / ไทย ที่มุมขวาบน โปรแกรมบันทึกการเลือกภาษาเป็นไฟล์ใหม่

หน้าบอร์ดและเฟิร์มแวร์มีสองโหมด:

- **3 Anchors · TDoA + AoA (3D)**: A1 เป็น Master, A2–A3 เป็น Slave และ Type2DK เป็น Tag ต้องมีอย่างน้อยหนึ่ง Anchor ที่วัดทั้ง Azimuth และ Elevation ได้และตรวจสอบแกนแล้ว
- **4 Anchors · TDoA (3D)**: A1 เป็น Master, A2–A4 เป็น Slave และ Type2DK เป็น Tag คำนวณจาก TDoA อย่างเดียว ต้องทราบพิกัดของทั้งสี่ Anchor และจัดวางนอกระนาบเดียวกัน A4 ใช้ Slave image เดียวกับ A2–A3 จำนวนสี่ตัวเป็นขั้นต่ำ ไม่รับประกันว่าจะได้คำตอบเดียวหรือความแม่นยำดีทุกจุด

ปิดพอร์ตและตัด RTLS ก่อนเปลี่ยนโหมด โปรแกรมเก็บค่า A1–A3 และ Tag ไว้เมื่อสลับโหมด และจำ A4 ในหน่วยความจำ ควรบันทึกโปรไฟล์สี่ตัวเพื่อใช้ครั้งต่อไป

## 2. Flash และเตรียมบอร์ด

ต่อ EVK ผ่าน USB ค้นหาพอร์ตและตรวจว่าพอร์ตใดเป็นบอร์ดใด โดยถอดทีละตัว กรอก EVK Revision ที่พิมพ์บนบอร์ด การ Flash USB อัตโนมัติรองรับ Revision 3 ขึ้นไป รุ่นเก่าต้องใช้ขั้นตอน SWD ของผู้ผลิต

เลือกชุดเฟิร์มแวร์ที่ครบถ้วน แล้ว Flash บอร์ดที่เลือก หรือ Flash Anchors ทุกตัวตามโหมด:

| บอร์ด / หน้าที่ | ไฟล์ |
| --- | --- |
| Type2BP A1 Master | `murata_2bp_master_v1.bin` |
| Type2BP A2/A3/A4 Slave | `murata_2bp_slave_v1.bin` |
| Type2DK ตั้งค่า | `murata_2dk_tag_setup_v1.bin` |
| Type2DK ใช้ถ่าน | `murata_2dk_tag_battery_v1.bin` |

ไฟล์อยู่ใน `firmware/releases/<เวลาที่ build>/` โปรแกรมอ่าน Manifest ตรวจ SHA-256 ใช้ DK6Programmer เขียนและตรวจ Flash แล้วอ่าน HELLO เพื่อยืนยันรุ่น หน้าที่ และเวอร์ชัน การยืนยัน HELLO ยังไม่ใช่ผลทดสอบ RF การสื่อสารปกติใช้ 3,000,000 baud ส่วนเครื่องมือ Flash ใช้ 1,000,000 baud ห้ามถอด USB ระหว่างเขียน โปรแกรมสร้าง Log ใหม่ทุกครั้งและไม่สั่งลบชิปทั้งหมดหรือแก้ OTP/การป้องกันชิป

Tag: กรอก MAC 8 ไบต์ที่ไม่ซ้ำและช่วง BLINK 100–10,000 ms เริ่มที่ 1,000 ms เลือก Tag แล้ว Flash โปรแกรมจะติดตั้ง image ตั้งค่า บันทึก MAC/ช่วงส่งใน PDM ติดตั้ง image ใช้ถ่าน และตรวจว่าค่ายังคงอยู่ จากนั้นปิด–เปิดไฟ Tag ถอด USB และทดสอบรับ BLINK เมื่อใช้ CR2032 อายุการใช้งานถ่านยังไม่ได้วัดจริง

### Flash เมื่อมีพอร์ต USB ว่างเพียงพอร์ตเดียว

เลือกบอร์ดในช่องเป้าหมาย กำหนด COM และ EVK Revision เฉพาะบอร์ดนั้น แล้วกด **Flash บอร์ดที่เลือก** ช่องพอร์ตของบอร์ดอื่นเว้นว่างและ Revision ยังไม่ทราบได้ ไม่ต้องกรอกพิกัด ทิศทาง หรือขอบเขตพื้นที่เพื่อเตรียมบอร์ดทีละตัว โปรแกรมยังตรวจ Revision และความสมบูรณ์ของไฟล์ ส่วน Tag ต้องมี MAC และช่วง BLINK ที่ถูกต้อง

รอจนการเขียน ตรวจ Flash และตรวจ HELLO เสร็จทั้งหมดก่อนถอด เปลี่ยนเป็นบอร์ดถัดไป ค้นหาพอร์ตใหม่ เลือกเป้าหมายใหม่ แล้วทำซ้ำ ใช้พอร์ต COM เดิมซ้ำได้ ถ้า Windows กำหนดชื่อ COM ใหม่ให้เลือกชื่อใหม่ อย่าถอด Tag จนติดตั้งทั้ง image ตั้งค่าและใช้ถ่าน พร้อมตรวจค่าที่บันทึกเสร็จแล้ว

**Flash Anchors ทุกตัว** เป็นคำสั่งแบบกลุ่มและต้องมีพอร์ตที่ไม่ซ้ำกัน ส่วนตอนวัดตำแหน่งจริงยังต้องเชื่อมต่อ Anchor ให้ครบสามหรือสี่ตัวพร้อมกันและมีพิกัดที่สำรวจแล้ว

## 3. สำรวจตำแหน่ง Anchor

หน้าสำรวจและสอบเทียบให้กรอก X/Y/Z ที่วัดจริง หน่วยเมตรในกรอบพิกัดของแผนที่ RTLS แกน +Z ชี้ขึ้น ค่าเริ่มต้นไม่มีพิกัดที่สำรวจ บอร์ดไม่สามารถหาพิกัดแผนที่และทิศหันที่แท้จริงให้เองได้ ต้องกำหนดจุดกำเนิด ทิศแกน และสเกลให้ตรงกับแผนที่

ID เริ่มต้นคือ KMUTNB-RF-A1 ถึง A4 และ KMUTNB-RF-T1 ส่วน MAC เป็นที่อยู่ทางวิทยุอีกชุดหนึ่ง ต้องไม่ซ้ำกัน และควรแยกจากอุปกรณ์ของ Simulator

โหมดสี่ตัวต้องจัดวางให้ครอบคลุมปริมาตร การมีความสูงต่างกันเพียงอย่างเดียวไม่ได้ยืนยันว่าไม่อยู่บนระนาบเดียวกัน โปรแกรมตรวจ Rank ของผลต่างพิกัด ตัวอย่างเพื่อวางแผน: A1=(0,0,0), A2=(10,0,0), A3=(0,8,0), A4=(0,0,4) ตัวเลขนี้เป็นตัวอย่าง ไม่ใช่พิกัดจริงของ KMUTNB กำหนดขอบเขตพื้นที่ให้สอดคล้องกับจุดที่ Tag ใช้งาน

โหมดผสม: กรอก Yaw/Pitch/Roll หรือใช้โหมดตรวจสอบเพื่อเก็บมุมจาก Tag ที่ทราบพิกัดอย่างน้อยสามทิศทางที่ไม่ซ้ำแนว รวมจุดต่างระดับ Azimuth วัดจาก +X ไป +Y, Elevation ไป +Z และใช้การหมุน Rz(Yaw) Ry(Pitch) Rx(Roll) ต้องตรวจแกนเสาอากาศ EVK และเครื่องหมายมุมกับบอร์ดจริง หลัง Fit ให้ตรวจจุดอ้างอิงอื่นก่อนติ๊ก 3D AoA โปรแกรมไม่ติ๊กยืนยันให้อัตโนมัติ

โหมด TDoA สี่ตัว: ไม่ต้องยืนยัน AoA โปรแกรมไม่ใช้มุมใน Solver แต่ RX Bias ยังมีผลต่อเวลา กำหนดค่าความคลาดเคลื่อนและเกณฑ์ความไม่แน่นอนจากการวัดจริง ค่าเริ่มต้นเป็นเพียงจุดเริ่มทดลอง บันทึกเป็นโปรไฟล์ใหม่ทุกครั้ง

## 4. รับข้อมูลและคำนวณ

หน้าตำแหน่งแบบเรียลไทม์: เปิด Anchors + บันทึก แล้วเริ่ม Anchors หากจะเก็บมุม ให้ใช้โหมดตรวจสอบซึ่งไม่คำนวณหรือส่งตำแหน่ง

PC ตรวจ HELLO ส่งการตั้ง MAC/ช่วงส่ง และรอ ACK จาก Anchor ทุกตัวก่อนเริ่ม A1 ส่ง RF SYNC ทุก 500 ms Slave ทุกตัวต้องมี SYNC ที่สอดคล้องกันอย่างน้อยหกตัวอย่างและยังไม่เก่า PC ชดเชย Offset/Drift จับคู่ BLINK เดียวกันจากทุก Anchor แล้วคำนวณ โหมดสี่ตัวจะไม่สร้างตำแหน่งเมื่อขาด A4 เวลา USB ใช้ตรวจความสดของข้อมูล ไม่ใช่เวลา RF สำหรับ TDoA

แสดง X/Y/Z เฉพาะตำแหน่งที่ผ่านเกณฑ์ โปรแกรมปฏิเสธเมื่อข้อมูลไม่ครบ นาฬิกาไม่พร้อม TDoA เป็นไปไม่ได้ การจัดวางไม่เหมาะ ผลวัดไม่สอดคล้อง มีสองคำตอบที่เป็นไปได้ หรือความไม่แน่นอนเกินเกณฑ์ ดูเหตุผลใน Log และ JSONL ไม่ควรเพิ่มเกณฑ์เพียงเพื่อให้ผ่านการจัดวางที่ไม่เหมาะสม

## 5. เชื่อม RTLS Platform

ลงทะเบียน Gateway สำหรับบอร์ดจริงใน Site/Floor ของ KMUTNB และรับ Gateway ID กับ Bearer Token รหัสผ่าน Dashboard ไม่ใช่ Gateway Token สร้าง Anchor ID พร้อมพิกัดที่สำรวจ รวม A4 ในโหมดสี่ตัว ปุ่มส่งออกพิกัดสร้างไฟล์สำหรับตั้งค่า ไม่ได้แก้ Server ให้อัตโนมัติ

กรอก Gateway ID/Token ตรวจสอบการตั้งค่า แล้วเชื่อมต่อ โปรแกรมตรวจ Site/Floor/Anchor และพิกัดให้ตรงกันภายใน 1 ซม. สามารถบันทึก Token ด้วย Windows DPAPI ซึ่งผูกกับผู้ใช้ Windows นี้ เมื่อเปิดการส่งตำแหน่ง โปรแกรมส่งเฉพาะผลสดที่ผ่านเกณฑ์ และส่ง `num_anchors_used` เป็น 3 หรือ 4 ตามผลจริง พร้อม Heartbeat/Status และข้อมูลดิบ RF หากเลือกส่ง โปรแกรมตรวจ ACK ของ Socket.IO และแสดงจำนวนข้อความผิดพลาด/ตกหล่น

Dashboard เริ่มต้นคือ [KMUTNB RTLS](https://uwb.mangosgo.com/?siteId=ca29a1a6-76c5-48ed-9c9a-e4615fcb4d09&floorId=58afbe99-a0a9-4fd2-ba69-4bf9acc96f6a) โปรแกรมไม่สร้างข้อมูลเข้าระบบหรือแก้แผนที่ตอนเปิด การยืนยันผล RF จริงจนถึงหน้า RTLS ต้องทดสอบภายหลังด้วยบอร์ดและ Token ของคุณ

## 6. เล่นย้อนหลังและตรวจรับ

หยุด Anchors ปิดพอร์ตและตัด RTLS ก่อนเล่นย้อนหลัง โปรแกรมคำนวณจากไฟล์ในเครื่องและไม่ส่งตำแหน่งย้อนหลังไปคลาวด์ แต่ละ Session มีโหมดและพิกัดที่ใช้วัด

ตรวจรับทีละขั้น: Flash/HELLO ของทุกบอร์ด, SYNC ทุก Slave, BLINK ครบทุก Anchor, จุดอ้างอิงต่างความสูง, การปฏิเสธคำตอบกำกวม, ถอด Anchor หนึ่งตัว, รีเซ็ตนาฬิกา, Tag ใช้ CR2032 และตำแหน่งสดบน RTLS บันทึก Ground Truth, Error Median/95%, อัตราอัปเดต และจำนวนผลผ่าน/ปฏิเสธ ผลทดสอบซอฟต์แวร์ไม่ใช่ค่าความแม่นยำ RF ที่วัดจริง
